## 4. Deep-Dive: Artifact Provenance & `p2_compounds.parquet`

### 4.1 What is `artifacts/p2_compounds.parquet`?
`p2_compounds.parquet` is a 62 KB tabular artifact produced during Phase 2 by `scripts/t2_02_splits.py`. It summarizes the 550 unique compounds in the MassBank development corpus, listing:
- `group_key` (identifier)
- `inchikey_first_block` (connectivity key)
- `smiles` (canonical chemical structure)
- `mix`, `precursor_mz`, `n_energies`
- `murcko` (Bemis-Murcko scaffold)
- `scaffold_group` (scaffold cluster)
- `is_acyclic` (boolean flag)
- `cluster`, `cluster_group` (Butina fingerprint cluster)
- `in_confirmation` (boolean flag allocating the sealed 20% confirmation set of 110 compounds vs the 80% development set of 440 compounds)

### 4.2 Provenance Chain:
```
Raw MassBank LCSB records (data/massbank/MassBank-data/LCSB)
  │
  ▼ scripts/t1_build_trajectories.py
artifacts/trajectories.parquet
  │
  ▼ scripts/t2_01_prereg_diagnostics.py
artifacts/p2_dev_corpus.parquet
  │
  ▼ scripts/t2_02_splits.py
artifacts/p2_compounds.parquet + artifacts/confirmation_set_sealed.json (json is tracked)
```

### 4.3 Git-Tracking Status:
- Ignored by `.gitignore` rules:
  - Line 34: `artifacts/*`
  - Line 59: `*.parquet`
- The provenance hash and confirmation partition keys are tracked in `artifacts/confirmation_set_sealed.json`, but the intermediate parquet binary is excluded by design.

### 4.4 Code Consumers:
- `src/muru/synth/generators.py::load_dev_covariates()` reads `p2_compounds.parquet` and `p2_descriptors_tierA.parquet` to filter out confirmation compounds and provide 440 compound descriptors for Phase 3 / OV synthetic world generation.
- `scripts/t2_03_descriptors.py` reads `p2_compounds.parquet` to build tier descriptors.
- `tests/test_confirmation_seal.py`, `tests/test_p3_seal.py`, and `tests/test_p3_generators.py` check its existence with `pytest.skip` guards.
- `tests/test_ov_pipeline.py` and `tests/test_ov_blinding.py` invoke `load_dev_covariates()` without a skip guard.

### 4.5 Scientific Independence of the Prospective Paper Benchmark:
`src/muru/paper_benchmark/` has **zero** dependencies on `p2_compounds.parquet`, `muru.synth`, `muru.objval`, or any real-data artifacts. The paper benchmark constructs its own 180-compound synthetic covariate matrix from pure numerical generators (`src/muru/paper_benchmark/generator.py`).

### 4.6 Artifact Classification:
- **`TEST_FIXTURE_PACKAGING_GAP`**: The 17 test failures in `tests/test_ov_*` are purely a packaging defect in the test fixtures (omission of `pytest.skip` when the generated artifact is absent).
- **`HISTORICAL_ONLY_REPRODUCIBILITY_GAP`**: If an external researcher seeks to regenerate Phase 3 / Objective Validation synthetic worlds from scratch, they must first acquire MassBank raw data and run the Phase 1/2 scripts.
- **NOT A BLOCKER**: Does not block prospective paper-benchmark reproducibility or execution.

## 6. Path Dependencies, Worktree & Environment Assumptions

### 6.1 Hardcoded Absolute Paths
- **`artifacts/MANIFEST_massbank.json` (Line 9):**
  `"root": "/Users/aryav/Documents/MURU-ConjectureLab-v1/data/massbank/MassBank-data/LCSB"`
  - `src/muru/io/manifest.py:117` uses `base = Path(root if root is not None else self.root)`.
  - Calling `Manifest.read("artifacts/MANIFEST_massbank.json").verify()` without passing `root` looks for `/Users/aryav/...` and fails on clean clones.
- **Documentation & Runbooks:**
  - `ops/MURU_DEVELOPMENT_EXECUTION_RUNBOOK.md`, `ops/MURU_HELDOUT_EXECUTION_RUNBOOK.md`, and `ops/MURU_EXECUTABLE_FREEZE_RUNBOOK.md` contain hardcoded paths (`/Users/aryav/Documents/MURU-ConjectureLab-v1`).
  - These should use `$REPO_ROOT` or relative commands.

### 6.2 Worktree Assumptions
- `tests/test_a3_4_temporal_provenance_erratum.py` checks `git_output("rev-parse", "HEAD") == git_output("rev-parse", f"{ERRATUM_TAG}^{{}}")`.
  - When subsequent engineering commits are applied on top of the erratum tag (e.g. on `eng/muru-rc4-a3-4`), `HEAD` advances and this assertion fails. It should assert `git merge-base --is-ancestor` or verify tag commit identity directly rather than demanding `HEAD == TAG`.

### 6.3 Environment Variables
- `MURU_THREADS` is used in baseline models (`scripts/t2_05_baselines.py`, `scripts/t2_07_controls.py`) and defaults cleanly to `"4"` or `"1"`.
- BLAS/OpenMP/MKL thread variables (`OMP_NUM_THREADS=1`, `OPENBLAS_NUM_THREADS=1`, etc.) are explicitly enforced across discovery scripts to guarantee numerical determinism.
