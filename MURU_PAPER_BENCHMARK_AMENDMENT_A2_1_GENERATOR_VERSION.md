**Reason for A2.1.** Amendment A2 changed the generator's scientific behavior
for F16 — it now emits a non-neutral M3 low-energy ceiling where it previously
emitted none — but left `GENERATOR_VERSION` at `paper-benchmark-generator-1.0.0`.
A version identifier that does not change when the generator's behavior changes
is a provenance defect: it cannot distinguish, from the string alone, the
pre-repair generator that produced 03cc4d3's byte inventory from the
post-repair generator that produces it after 03cc4d3. This amendment corrects
only that identifier.

**Scientific change in A2.1: NONE.** A2's accepted F16 repair — its
mathematical form, its M1/M2/M3 amplitudes, its declared truth, its case
population — is not revisited, and this document does not reopen it.

**Development outcomes observed: NONE. Held-out outcomes observed: NONE.** No
Development or Held-out scientific outcome was executed, scored, enumerated,
parsed, summarised, or inspected in preparing this amendment. Case content was
regenerated and hashed, and every comparison below is either mechanical git
byte-hashing of tracked source paths or whole-object equality of `inputs`/
`truth` sub-objects with `content_hash` excluded; no response value was
decoded and no case was fitted, scored, or evaluated for detectability.

## A2.1.1 Version convention used

The repository already has a convention stronger than a bare `X.Y.Z`:
`GENERATOR_VERSION`, `ADEQUACY_CONTRACT_VERSION`, `TruthRecord.truth_version`,
and every manifest `version` field follow `paper-benchmark-<component>-X.Y.Z`.
A2.1 bumps within that convention:

```
GENERATOR_VERSION: "paper-benchmark-generator-1.0.0" -> "paper-benchmark-generator-1.1.0"
```

A minor-version bump, because the generator's behavior changed for one frozen
family (F16) while every other family's behavior and the payload schema are
unchanged — backward-compatible in shape, not in every case's bytes.

`TruthRecord.truth_version` (`"paper-benchmark-truth-1.0.0"`) is **not**
changed. It names the `TruthRecord` dataclass's field set — `case_id`,
`partition`, ..., `expected_behavior` — and A2.1 (and A2 before it) adds,
removes, or renames no field on that record. It is a schema version, not a
generator-behavior version, and the schema is unchanged, so per the governing
instruction it is preserved.

## A2.1.2 The metadata vs. payload distinction, proved

`GeneratedCase.content_hash` is `SHA-256({"inputs": ..., "truth": ...,
"generator_version": GENERATOR_VERSION})`. Because `GENERATOR_VERSION` is part
of every case's hash pre-image, bumping it mechanically changes
`content_hash` for **all 380 cases** — not only F16's. That is exactly the
"version-metadata-only change" this amendment must be shown not to be confused
with a "scientific payload change."

A new helper, `generator.scientific_payload_hash(inputs, truth,
generator_version=None)`, hashes `{"inputs": ..., "truth": ...}` alone.
Passing `generator_version=GENERATOR_VERSION` (the default) reproduces
`content_hash` exactly; passing `None` yields a value stable across a future
version-metadata-only bump. This is a pure Python addition — it changes no
existing field, no artifact schema, and (verified below) no generated byte.

`scripts/pb_32_amendment_a2_1_integrity.py` rebuilds both the A2 (`03cc4d3`)
and A2.1 (current) generator states and compares every one of the 380 cases:

| Check | Result |
|---|---|
| Case records total | 380 |
| Case records with a payload difference (inputs/truth, `content_hash` excluded) | **0** |
| Case records with a `content_hash` difference | **380** |
| Row byte-length per stream (`content_hash` is fixed-width hex) | unchanged |

Per-stream detail (all six row files: `inputs/` and `truth/` ×
`development`/`held_out`/`challenge`):

| Stream | Lines | Payload changed | `content_hash`-only changed |
|---|---:|---:|---:|
| `inputs/development.jsonl` | 80 | 0 | 80 |
| `truth/development.jsonl` | 80 | 0 | 80 |
| `inputs/held_out.jsonl` | 240 | 0 | 240 |
| `truth/held_out.jsonl` | 240 | 0 | 240 |
| `inputs/challenge.jsonl` | 60 | 0 | 60 |
| `truth/challenge.jsonl` | 60 | 0 | 60 |

For all 361 non-F16 cases and all 19 F16 cases alike: covariates, scaffold
assignments, partitions, seeds, energies, generated responses, and truth
values are byte-identical to `03cc4d3`. The 19 F16 cases' scientific payload is
therefore, specifically, exactly the accepted A2 repair — the same shape
parameters, the same M1/M2/M3 amplitudes, the same truth. `content_hash` moved
for every case because the version string it is built from moved; nothing else
did.

## A2.1.3 Provenance tooling correction

`tests/test_paper_benchmark_amendment_a2_integrity.py` had pinned full
`content_hash` values for a sample of cases. Those pins are, by construction,
version-stamped — they would have gone stale on this bump regardless of
whether anything scientific changed, which is the wrong failure mode for a
"did A2 change any non-F16 science" test. They are replaced with
`scientific_payload_hash(..., generator_version=None)` pins, which state the
intended claim directly and survive a future metadata-only bump. Full
`content_hash` pins under `GENERATOR_VERSION = 1.1.0` now live in the new
`tests/test_paper_benchmark_amendment_a2_1_integrity.py`, where a version stamp
is exactly what is being certified.

`scripts/pb_31_amendment_a2_integrity.py`'s row comparison previously compared
raw JSON line bytes. After this bump every row's bytes differ from A1's
rebuild (via `content_hash`), which would make that script wrongly report a
breach of "only F16 changed" for a purely orthogonal reason. Its row and
manifest-derived comparisons are now payload-aware (`content_hash` stripped
before equality), so it correctly continues to report **19 F16 / 0 non-F16**
payload changes relative to A1, independent of the version bump. The
manifest-level comparison specifically was corrected to derive its changed-case
set from the row-level payload comparison rather than the case manifest's own
records, because a case-manifest record carries no `inputs`/`truth` — its only
payload fingerprint is `content_hash` itself, so stripping that field from a
manifest record (as opposed to a row record, which does carry the full
payload) would silently erase the only signal it has.

`scripts/pb_30_amendment_a1_integrity.py` now imports its allowed-path sets
from `pb_32` as well as `pb_31`, extending the per-amendment attribution
(`changed_by_amendment`, `added_by_amendment`) from two amendments to three.

None of this is a scientific correction. It is a correction to the tooling
that certifies scientific immutability, made necessary by, and scoped
exactly to, the version bump.
